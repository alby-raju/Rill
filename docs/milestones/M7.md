## gRPC

Request → gRPC loads binary descriptor sets or local .proto files and explicit additional import folders. The separately bundled official protoc 36.2 (from pinned SwiftProtobuf 1.39.0) emits descriptors with imports, without plugins or generated application stubs. Source preflight caps files at 128, 1 MiB/file, 16 MiB total and import depth 32; absolute/traversal/escaped import paths and symlink escapes reject. Compiler argv never enters a shell, its environment does not inherit credentials, output/diagnostics cap at 64 KiB each, and a ten-second deadline/cancellation terminates the owned child. Descriptors cap at 8 MiB/depth64, 20,000 symbols, 100,000 fields and 2,000 methods. Malformed/missing/ambiguous identities and unresolved imports/types reject. Extensions, legacy groups and Editions are explicitly unsupported. Reflection attempts v1, falling back to v1alpha only on unimplemented; it retrieves application symbols/imports within 128 services/files, 8 MiB aggregate descriptors and a 60-second overall cancellation deadline. Local descriptors remain usable when reflection is unavailable.

The independently authored dynamic codec uses validated descriptors and the official SwiftProtobuf well-known JSON implementation. It supports scalar fields, exact signed/unsigned 64-bit strings, bytes/base64, repeated packed/unpacked values, maps, enums, oneof selection, nested messages, required fields, unknown wire-field skipping and well-known timestamp/duration/struct/value/list/fieldmask/wrappers/Any. JSON inputs cap at 1 MiB; codec traversal at depth32/10,000 nodes. Unknown JSON fields, duplicate aliases/oneofs and invalid numeric ranges fail. Output follows Protobuf JSON conventions; this baseline is not a full cross-language conformance certification, and unsupported descriptor families are not silently translated.

The workbench filters methods by call mode and supports unary, client/server/bidirectional streaming through native HTTP/2, individual sends and explicit finish-sending. Cardinality is enforced over the shared native streaming framing. grpc/http explicitly selects plaintext; grpcs/https uses verified system TLS and hostname checks. Custom trust/mTLS profiles are not wired into this workbench yet. Metadata has 64 rows/16 KiB, lowercase names, printable ASCII strings and base64 -bin values; transport-owned/reserved keys reject. Environment/named-secret templates resolve only for explicit network actions. Native header lists cap at 16 KiB; messages at 1 MiB, queued sends at 16/4 MiB, deadline at 1–300 seconds and timeline at 1,000 records/8 MiB. Server error text is omitted; metadata/messages can contain sensitive content and stay transient. A terminal event has reserved timeline capacity. Cancel/leave/method changes cancel the owned call; delayed callbacks cannot mutate a subsequent session. No application-level retry/hedging policy is installed.

## MQTT

Request → MQTT / Kafka / AMQP Brokers contains explicit native sessions with independently scrolling settings and timelines. MQTT supports 3.1.1 and 5, tcp/mqtt plaintext and ssl/mqtts verified system TLS; ws/wss negotiate mqtt, preserve path/query and accept fragmented binary messages. Clean sessions have no automatic reconnect, redirect, persistent-session replay or will configuration. Connection/operation deadlines are editable; sessions cap at five minutes. Version 5 supports payload-format/content-type properties, server maximum QoS/retain/wildcard/packet/receive limits and server keepalive overrides. Topic aliases and enhanced authentication are not enabled; shared subscriptions and unsupported packets reject. This is a published subset, not every MQTT extension.

Subscribe waits for SUBACK and surfaces rejection. Publish topics are separate concrete destinations; wildcard publishing rejects. QoS 0 confirms a local write; QoS 1 waits for PUBACK; QoS 2 completes PUBREC/PUBREL/PUBCOMP. Incoming QoS 2 waits for PUBREL before delivery, acknowledges duplicates without redelivery and bounds pending state. This does not guarantee exactly-once behavior across crashes or discarded sessions. Payloads cap at 1 MiB; packet properties at 16 KiB, pending operations at 16, pending inbound QoS2 bytes at 2 MiB and the binary channel queue at 4 MiB. In-flight native writes cap at 16/4 MiB; timeline at 1,000 events/8 MiB. Protocol failures, rejected operations and cancellation close or fail explicitly. Settings/passwords are not auto-persisted; connection templates may resolve named secrets.

## AMQP

AMQP 0-9-1 uses a new bounded native codec and Network transport with explicit amqp/amqps, SASL/PLAIN and verified system TLS/hostname. Virtual-host, username/password and existing queue are explicit settings. The client opens one channel, configures prefetch16, consumes with acknowledgement after delivery callback and publishes through the default exchange with mandatory routing and publisher confirms. Consumption acknowledges/removes received messages; it is not a non-destructive browse mode. Missing queues/auth refusals and mandatory returns fail. No declare/bind/topology creation occurs. Publisher confirms require the broker's extension; plain AMQP without it is an unsupported compatibility case. Heartbeats, flow/blocked notifications, frame reassembly, content-type, large/empty bodies and redelivery metadata are handled. Queue deletion, transactions, topology administration, arbitrary exchanges and authentication families are not implied.

Frames negotiate 4–64 KiB, bodies cap at 1 MiB, field tables at 16 KiB/depth16/256 entries, one confirmed publication is active at a time, operations have deadlines and sessions have the shared five-minute/1,000-event/8-MiB limits. Closing drops the native connection and outstanding promises. An interrupted unacknowledged delivery can be requeued by the broker; Rill does not persist delivery state.

## Kafka and CloudEvents

Kafka uses the pinned beta Swift native client/librdkafka with statically built BoringSSL/zstd and system zlib; no JVM, JAR or system OpenSSL installation. Bootstrap hosts/topic/group/security/deadline are explicit. Plaintext, verified TLS, SASL/PLAIN over plaintext or TLS are supported. TLS receives system anchors as PEM and retains hostname/certificate verification; custom trust, client identities, SCRAM, schema registry and administration are separate work. Native metrics push/statistics/log output are disabled. Connecting queries existing metadata without creating topics. The selected partition, or all existing partitions up to16, is manually assigned from its current end with auto-commit and auto-offset-store disabled. Existing group commits are ignored. Group ID is a client context, not group balancing; partition start points are not an atomic cluster snapshot. Larger topics need an explicit single partition. Consumers never call commit/store APIs.

Publish waits for an all-replica acknowledgement, records partition/offset only on acknowledgement and reports failures. One publication is active, application retries are zero and idempotence is disabled. Native connectivity reconnection/discovery may continue until the five-minute session deadline; broker-advertised endpoints are part of explicit cluster connection. Bodies cap at 1 MiB, keys/headers at 16 KiB, native receive buffers at 2 MiB/client, consumer fetch/queue settings are bounded and timeline at 1,000 records/8 MiB. The C library owns decompression/allocation before Swift inspects decoded messages; fresh-machine/large compressed-batch acceptance remains required. Native queue bounds are per partition, not a promise of 8 MiB total process memory. Closing cancels owned service tasks; native shutdown is asynchronous.

Structured CloudEvents 1.0 generates UUID/source/type/RFC3339 time/specversion and parses exact JSON data before serialization. It caps the complete envelope at 1 MiB and rejects invalid attributes/data. Content type application/cloudevents+json is attached for MQTT5, AMQP and Kafka. MQTT3.1.1 cannot carry that metadata and rejects the structured metadata publish configuration. No binary CloudEvents binding or arbitrary extension catalog is claimed.
