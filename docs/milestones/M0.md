# M0: Foundation reliability

Status: first implementation slice. M0 and the overall roadmap are not declared complete. Core behavior is tested; installed-app UI, Keychain prompts and quit interactions still require manual evidence.

## Implemented behavior

### Workspace integrity and concurrent writers

`WorkspaceFile` validates the supported version-one schema, collection/request/environment/history identities, field identities within each editor, collection and selected-environment references, and finite positive request timeouts. History may outlive a deleted request. Unknown/corrupt schemas are preserved, not repaired in place. Version one is the only existing Rill schema; future migrations require explicit implementations and regression fixtures rather than blind decoding/re-encoding.

Reads are capped at 32 MiB, with JSON nesting checked before decoding (128 levels). Saves validate before creating a temporary file. New temporary files have mode `0600`; bytes are flushed before an atomic rename. Failed validation cannot replace the original. This provides atomic replacement, not a claim of recovery from every filesystem/power-loss failure.

`WorkspaceRepository` uses a nonblocking advisory file lock and a SHA-256 content revision, including a fresh storage nonce on every commit, across read/compare/write. Even an identical-content or credential-only save invalidates stale readers. A stale cooperating process cannot overwrite a different or externally deleted file. Lock contention fails visibly instead of blocking the UI. Non-cooperating external programs can still race outside the advisory lock; this is not a filesystem-wide locking guarantee.

The desktop serializes file and Keychain access on a separate actor. Saves debounce for 250 ms, retain in-memory edits on failure and expose pending/saving/failed/conflict states. Pure session-history changes do not save or invalidate other open instances. Conflicts pause further saves; export edits before reopening instead of overwriting the newer workspace. On normal quit, pending changes are flushed; a failed flush offers cancel or an explicit quit-without-saving choice. Forced termination recovery remains M1 work.

Keychain read/write/delete errors are no longer treated as empty credentials. Keychain reads/writes run under the same cooperative lock as their workspace operation. Credential mutations happen after the workspace revision is accepted, and successful writes are cached. Workspace and Keychain are separate stores, not one atomic transaction: a Keychain failure can leave the non-secret workspace saved while the credential remains pending in memory, and the UI must report the failure. Manual Keychain/quit validation remains outstanding.

Native import validates and builds a complete merged value, regenerates identities and strips incoming auth credentials before applying any edits. File reading/encoding/merging runs off the UI executor. A concurrently changed workspace aborts apply rather than losing edits. Import preview and foreign formats remain later roadmap work.

### Execution and resource policy

| Resource | Current policy |
| --- | --- |
| HTTP download | 16 MiB default; validated execution budget supports 1 byte–256 MiB for callers/tests. Known length is rejected early; actual received bytes enforce the limit even without a length. |
| Visible response preview | At most the first 512 KiB; truncation is labelled. Full accepted bytes remain available for raw copy/export. Large bodies bypass JSON formatting. |
| Session history | At most 50 exchanges and 32 MiB of retained bodies; session-only, not durable history. |
| Workspace file | 32 MiB input/output and 128 JSON nesting levels on decode. |
| HTTP timeout | Finite positive input; existing 1–300 second transport clamp retained. |

`RequestEngine` remains the shared preparation/execution/check path. It rejects invalid timeout values, repeated header names it cannot faithfully represent, and control characters in user headers, generated Content-Type and Bearer auth. HTTP elapsed duration uses a monotonic uptime clock.

Cancellation stops the active transport. Navigation or edits to the current request/environment clear the response and cancel the old task; an execution context prevents stale results/errors being presented. Generation guards keep cancelled task cleanup from clearing a newer request. Background responses must not overwrite the current request context. Manual UI race validation is still required; core context and transport tests cover the underlying policies.

Future stream/run/archive/subprocess budgets will be enforced by their own implementations; this slice does not claim those nonexistent paths are already complete.

### Allowlisted diagnostics

File → Export Support Diagnostics writes a private JSON report containing app/OS/architecture/schema versions, entity counts, persistence health, configured response limits and an enumerated last-failure category. It never serializes a request, workspace, raw error/userInfo, log, identifier, URL, header, credential, environment value or body. Seeded-secret tests exercise the allowlist. The report does not currently identify an exact compiler build; release/toolchain provenance remains future work.

### CI and owner-approved governance

The workflow checks the roadmap and runs release builds plus the full fixture-backed test suite on macOS 15 Apple Silicon/Xcode 16.4, macOS 15 Intel/Xcode 16.4 and macOS 15 Apple Silicon/Xcode 26.3. A stable aggregate job named `Build and test on macOS` fails if any matrix entry fails or is cancelled/skipped.

GitHub's active default-branch rules require this check from the GitHub Actions integration and an up-to-date PR branch. Existing PR, force-push and deletion restrictions remain. On 2026-10-24 the owner explicitly chose to preserve the repository's administrator bypass and one approving review; this is an approved deviation from the original no-bypass roadmap wording. We will not use that bypass to self-merge implementation PRs automatically.

Runner labels and Xcode availability were checked against [GitHub's runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) and [macOS image inventory](https://github.com/actions/runner-images/blob/main/images/macos/macos-15-Readme.md) on 2026-10-24. CI is build/test coverage, not installed-app support certification.

The independent implementation/dependency review policy is in [CONTRIBUTING.md](../../CONTRIBUTING.md). No new external Swift dependency or original Relay source was introduced by this slice.
