# M5: Definitions, contracts, mocks and inspection

Status: implementation delivered for the subset below; required CI and installed-app/independent consumer acceptance are separate evidence. No reference-archive implementation, tests, fixtures or assets are reused.

Request → API Definitions / Contracts / Mocks opens four tools. Local JSON/YAML and explicitly entered URLs load OpenAPI 3.0/3.1/3.2 or Swagger 2.0 descriptions. No external references/examples, OAuth discovery or application endpoints are fetched automatically. Remote loading uses bounded native GET/default trust/same-origin redirects; local files use the no-follow bounded reader. Inputs cap at 8 MiB, 2,000 operations and 16 MiB aggregate generated metadata. Unsupported native methods (TRACE) are disclosed as omitted; QUERY/additional-operation representations and unsupported body/serialization families fail explicitly. Version acceptance is not full specification validation.

Generation groups requests by first tag (or API title), resolves first-server defaults and local refs, maps supported path/query/header parameters, basic/bearer/header-or-query API-key metadata, raw JSON/text and Swagger text/form bodies, examples/defaults/bounded samples, and concrete documented success statuses. OAuth/OpenID metadata remains in the source and requires explicit native auth setup. Cookie auth, AND-security extras and missing/generated required examples appear as setup gaps; credentials are never invented. Unsupported array/object parameter serialization, arbitrary styles, multipart/file request bodies, external refs and recursive sample graphs fail explicitly. Generated positive expectations are linked to their source; they do not claim negative-case coverage or valid credentials. Samples are heuristics, not proof of schema satisfaction.

Source snapshots persist in the native workspace and backups alongside generation baselines and operation links. They may contain sensitive examples and remain plain text. Apply previews added/changed/removed/config-only/locally edited classifications before committing. Request identity survives refresh. Locally edited requests remain intact; removed edited requests are kept unlinked. Baseline collection identity preserves renamed collections. Schema/example changes participate in canonical fingerprints independent of JSON formatting/key order; shared-schema changes can conservatively mark multiple operations changed. Stale workspace/repository revisions reject. Apply is an atomic metadata-only commit, refuses credential changes/deletion of nonempty credentials and never stages new Keychain values. Native imports remap source links and reset baselines for review. Foreign exports omit source links/contracts.

## YAML and JSON Schema

API YAML opts into completed prior anchors/aliases with independent preflight limits: 100,000 events/expanded nodes, expanded bytes 32 MiB, container depth 64, scalar 1 MiB and anchor name 128 bytes. Recursive/forward/duplicate anchors, merge keys, custom tags and multiple documents reject. Plain flow maps and folded/literal blocks work. Foreign workspace importers retain their default alias prohibition. JSON remains exact through the independently authored parser. YAML supports exact signed 64-bit integer literals; floating numeric inputs are conservatively limited to 15 normalized significant digits and exponents ±100 before Foundation conversion. Use JSON for larger or more precise numbers. [Parsing decision](../decisions/api-definitions.md).

The Schema tab validates a published subset: boolean schemas; type (including integer and type arrays), required/properties/additionalProperties, enum/const, homogeneous items, minimum/maximum/exclusive bounds, string/array/object size bounds, nullable, allOf/anyOf/oneOf and local JSON Pointer refs. Exact decimal comparison avoids Double rounding; strings count Unicode scalars. Validation caps input 8 MiB, depth 64, 10,000 evaluation/inspection nodes, 1,000 findings, 128 unsupported keywords and numeric mantissas 4,096 digits. Cyclic refs at the same instance location fail; finite nested instances remain bounded.

Unknown validation keywords, external refs, nested $id scopes, patterns, tuple/prefix items, uniqueItems, multipleOf, conditional/dependent/unevaluated rules and unsupported dialect-specific assertions cannot pass. Title/description/default/examples/format/readOnly/writeOnly/discriminator/XML metadata are annotations, not additional assertions; format validation is not claimed. This is not a full dialect/meta-schema validator. Findings omit instance values but paths may contain user-supplied property names; review before sharing.

## Contracts

Linked requests default to contract checks; Workflow offers an explicit toggle/unlink. The native send engine validates the same frozen request it sends, without a second variable expansion, and appends response checks before extraction/post-hooks. Desktop sends, collection, matrix and load all receive the saved source snapshots.

Request checks cover method/path suffix, required path/query/header/cookie fields, supported scalar parameter schemas, JSON/text bodies, documented media type and security-header/query presence. They do not prove credential validity or server identity beyond native TLS. Unsupported form/streamed body schemas and serialization rules reject before traffic. Responses check concrete/wildcard/default status, required/typed headers, documented media type and supported complete body schemas. Missing media headers, malformed JSON and unsupported rules fail. Required request failures report a generic message without URLs/body/credentials; the schema workbench can inspect a specific rule offline. Full request-content families, all security combinations and format-specific serializers remain acceptance gaps.

## Mocks and inspection

Mocks use a new native loopback-only HTTP listener, with explicit start/stop, port 0/free-port selection, conflict handling, 32 connections, 5-second connection/startup limits, 16 KiB request headers and 1 MiB request body cap. HTTP/1.0/1.1 with Content-Length is supported; chunked/Expect/pipelining/duplicate headers are not a general web-server compatibility claim. Routes match method and static/{parameter} path segments. Responses have controlled length/connection framing; HEAD omits payload and 204/304 omit bodies. Routes cap at 1,000, 1 MiB/body, 16 MiB aggregate body data, 100 ASCII headers/16 KiB per route and 4 MiB aggregate header text. Editable route JSON caps at 2 MiB. Closing the tools window stops the listener. No scripts or arbitrary interfaces execute/bind.

Definition routes use documented successful examples or bounded samples; users can edit every route before starting. Root path templates are used; server/base-path prefixes may need manual route adjustment. Route generation cannot certify schema conformance. Samples cap depth16, 10,000 nodes and 1 MiB output; cyclic/explosive graphs fail before expansion becomes unbounded.

Passive checks use an existing response without traffic: HTTPS HSTS max-age, HTML CSP presence, nosniff and basic CORS/cache hygiene. These are contextual indicators, not a security certification. Active probes are a separate explicit action with a visible URL/method: unauthenticated GET/HEAD only, one existing query value with quote or unique reflection marker, or at most ten sequential rate samples with pacing. They do not execute hooks or use selected request auth/header state. Redirects are disabled so probes do not silently multiply requests. Responses cap at 1 MiB and timeout at ten seconds; cancellation stops owned work. Reflection/server errors do not prove injection; absence of 429 does not prove missing rate limits. No fuzzing, exploit chain or invasive scanner is claimed.

## Evidence

210 local tests pass: exact schema boundaries/combinations/UTF-8 keys/unsupported refs; YAML default refusal, opt-in aliases, scalar/recursive/expanded-size bombs; request generation and JSON/YAML/Swagger mapping; refresh identity/local edits/removal/config/stale-preview cases; native source remapping; required parameters, media and response schema failures; real mock route/contract execution, port conflict/restart; passive checks and loopback active probes; atomic metadata-only Apply/reopen/stale external revision; bounded sample expansion, route codec failures and redirect refusal. Existing tests retain import, credentials, TLS, uploads, runner and generated-client coverage. Required CI must also pass all three macOS configurations and 72 generated-program loopback cases.

Manual installed-app editing/overwrite/Keychain and independent OpenAPI/Allure/producer acceptance remain pending, so M5 rows stay partial. Broader schema dialects, serialization/auth combinations, richer diff UI, persistent mock-route catalogs and non-loopback server bindings are not claimed.
