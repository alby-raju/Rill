# M8 — headless execution and collaboration

The independently authored RillCLI executable consumes RillCore, including the same preparation, authentication/TLS selection, runners, reports, imports, API definition refresh and protocol sessions as the desktop. `docs/CLI.md` and `--help` describe the complete command matrix. Native subprocess tests cover fresh-directory help/version/init/exclusive writes/quiet, actual HTTP checks and transport failures, reports/raw exports, backup/restore/import preview/apply GraphQL success/errors, OpenAPI refresh identity retention, SSE/WebSocket privacy summaries and SIGINT exit130/listener cleanup. CLI gRPC sends one message then half-closes; interactive multi-message streaming remains desktop behavior. PKCE remains the browser-assisted desktop flow; CLI OAuth is explicit client credentials with named Keychain destination.

Git operations select a portable checkout outside Rill's runtime directory. Init/status/export/commit are explicit. Commit is restricted to workspace.json/.gitignore and refuses unrelated staged files. Keychain credentials and history are omitted, while entered field/body/environment data remains for review. Hooks, automatic signing, fsmonitor, auto-GC and lazy fetch are disabled; no remote commands run. Only use a trusted checkout: Git configuration/attributes are not an OS sandbox. Local tests exercise a real Git repository and a failing hook to establish that hooks do not execute.

The read-only sharing listener defaults to 127.0.0.1, requires a 32–256-character access token, compares token hashes without early exit, accepts GET/HEAD only, and serves a frozen sanitized snapshot. Explicit LAN mode warns about plaintext transport and retained names/hosts/paths. It bounds four connections, 8 KiB request headers, five-second startup/header waits and an 8 MiB response. Pull accepts verified HTTPS or literal loopback HTTP by default, refuses redirects and existing destinations, validates and sanitizes the versioned document, regenerates identities and writes a private file. Transport has the shared 16 MiB response cap before the stricter 8 MiB share decoder. Real loopback tests exercise missing/wrong tokens, sanitized content, fresh IDs, mutation rejection and overwrite refusal.

Local extension API v1 discovers reviewed JSON data services only. Manifests expose stable IDs/names/versions and request-template/mock-route services initialized with API-version/workspace-count context. The catalog is bounded to 128 directories, 32 services each, 64 KiB manifest, 1 MiB service and 16 MiB aggregate content. Symlinks/path traversal are rejected. Explicit approval stores exact manifest/content SHA-256 fingerprints; re-discovery immediately before use invalidates modified content. Templates get fresh identities, detached auth/TLS/schema links and disabled hooks/automatic introspection. Mock services export validated MockRouteFile JSON. No Java plugins, native dynamic libraries or scripts execute. Tests prove disabled/modified services cannot register and malformed trust files fail. Arbitrary executable plugin compatibility is outside this data-only contract.

The native Git/sharing/extensions sheet offers these explicit operations and cancels/stops owned listeners on closure. Installed UI, Keychain prompts, LAN firewall behavior, and independent service interoperability remain manual acceptance items; these rows stay partial until evidence is recorded.

Packaged-artifact acceptance additionally mounted the development DMG read-only outside the checkout, ran CLI version/help/init/list and overwrite refusal, verified bundled help/protoc, compiled an offline Timestamp import, and interrupted an active HTTP run with exit130 plus a persisted cancelled report. These checks do not establish installed UI/Keychain/provider acceptance.
