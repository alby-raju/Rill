# M3: Interchange and generated clients

Status: in progress. Implementation is independent of the original archive. Foreign formats and generated client targets are tracked separately; no universal compatibility is claimed.

## Slice 1: Native import plans

IO-01/08: native import now prepares and validates an immutable plan before showing collection/request/environment/auth/TLS/secret-descriptor counts, request names and specific warnings. Cancel applies no incoming data. Auth values are discarded; identities are regenerated; collisions, file-reference handling, local/process references, insecure TLS and client-identity reselection are disclosed. No referenced file is read and no network request is sent by preview.

Apply verifies that saved user data still matches the preview baseline while preserving new session-only exchanges. It then atomically commits the complete bounded native workspace before publishing it to the UI. Native imports contain fresh request identities with no credentials, so this path needs no Keychain writes and cannot fail after a metadata commit because a companion credential deletion was denied. Existing secrets stay unchanged. External/stale file revisions still reject the commit. Existing pending structural edits are flushed before building the preview; separate request drafts remain untouched.

Five new tests bring the suite to 112 cases: preview warnings/counts without mutating input or exposing seeded credentials, stale user edits versus preserved session activity, pure import under denied companion writes, concurrent external import protection and invalid-plan/export destination preservation. Installed-app preview/cancel/apply and disk-permission failure checks remain pending. IO-01/08 remain partial; foreign formats and shell/snippet paths are subsequent slices.

## Slice 2: Safe command interchange

IO-02, CODE-01/04: native POSIX-word parsing for one cURL/HTTPie command, with balanced quoting, literal quote/backslash/newline handling and line continuations. Shell variables/substitutions/backticks outside literal single quotes, command lists, pipes and redirects fail. There is no shell invocation, implicit stdin or file content read during import. Commands are capped at 1 MiB/10,000 arguments and parsing is cancellable.

Supported cURL scope: explicit method/URL, unique headers, Basic/Bearer/common API-key headers, max-time, raw/JSON/URL-encoded data, encoded GET parameters, binary file references and simple multipart text/file metadata. Supported HTTPie scope: method/URL, header/query items, string/typed JSON values, forms and simple file parts, raw bodies, Basic/Bearer and timeout. Pasted file references are unresolved metadata and must be selected on this Mac before Send. Unknown/lossy flags and combinations fail; redirect/compression/display differences are warned. No script, config, netrc, cookie-file, proxy, output or TLS-override command option is executed/imported silently. Native TLS must be configured explicitly.

Preview exposes warnings before Apply. Recognized auth credentials move to Auth/Keychain; unknown Authorization remains a disclosed plain-text header. Command Apply stages a fresh credential under the same cooperative revision lock before the atomic metadata write. Denied credential writes preserve the workspace. Failed file writes remove the staged credential; cleanup failure reports a possible unreferenced Keychain item instead of claiming rollback succeeded. Existing secrets are never overwritten by the fresh request identity. This remains compensation across separate stores, not a power-loss-atomic transaction with Keychain.

Generation freezes the current request with selected environment/auth/secret references once and sends no traffic. Output uses quoted POSIX arguments, disables implicit cURL config loading, and disables HTTPie stdin/netrc lookup. Unspecified imported client defaults use Rill behavior; reconstructed HTTPie JSON whitespace may differ. Common credential headers and the selected API-key header are masked by default; explicit opt-in reveals them. URLs, bodies, paths and uncommon headers may still contain private data, disclosed in the UI. cURL binary bodies retain local file references (the file may change after generation). Inline bodies are UTF-8 and bounded to 1 MiB. Multipart/TLS-profile snippets, repeated headers and HTTPie binary bodies currently fail explicitly and remain scope for later M3 slices. Changed settings/drafts and dismissed views cannot publish stale generated output; owned workers cancel.

Fourteen new tests bring the suite to 126 cases: literal quoting, prohibited shell syntax, common command fields/body/auth, encoded/empty GET and POST semantics, unresolved file/multipart metadata, unsupported flags, typed HTTPie JSON and part ordering, frozen URL/header/body/timeout round trips, masked/explicit credentials, supported binary references, denied credential/failed-file compensation and retry, secure imported credential storage, plus an actual system-cURL subprocess against the loopback fixture. The app's importer/generator never starts that subprocess; it exists only in tests. HTTPie executable interoperability and installed-app preview/generation/Keychain tests remain pending, so these rows stay partial.

Primary syntax references checked on 2026-10-24: [cURL manual](https://curl.se/docs/manpage.html) and [HTTPie CLI documentation](https://httpie.io/docs/cli). Rill deliberately supports the documented subset above, not every CLI flag, expansion or plugin.

## Import validation resource refinement

Environment hierarchy validation now indexes and memoizes shared parent chains once instead of repeatedly constructing/resolving the complete graph per environment. Parent choices account for the entire descendant subtree, preventing an apparently valid parent edit from pushing a child beyond 64 levels. Native import reuses one secret-reference pattern and skips rewriting when there are no descriptor mappings. Preview names use a 512-byte UTF-8 prefix (with replacement/ellipsis when truncated), while saved names remain unchanged.

Four additional cases bring the suite to 130 tests: a 5,001-environment shared graph, cached-depth/descendant/cycle boundaries, a long combining-character preview name, and Unicode comparison/summary bounds. This is core validation evidence, not a large-workspace UI performance claim. Archive and foreign-format scope remains open.

JSON comparison now compares decoded UTF-8 sequences literally for keys and string values, avoiding Swift canonical-equivalence merging of distinct JSON names. Summaries are byte-bounded even for long combining sequences. This follows the interoperable comparison guidance in [RFC 8259 §8.3](https://www.rfc-editor.org/rfc/rfc8259#section-8.3), checked 2026-10-24; escaped forms still decode before comparison.

## Slice 3: HAR request selection

IO-06/08 now support pasted UTF-8 HAR 1.2 logs (including BOM), bounded to 32 MiB/depth 128, 1,000 entries and 10,000 headers/form fields per request. Preview selects one entry at a time; Apply uses the existing compensated fresh-request Keychain transaction. Encoded URLs are authoritative, preventing duplicate query parameters. Raw postData text and ordered URL-encoded forms are supported. Recognized auth headers/URL credentials move to Auth; other headers/URLs/bodies remain potentially sensitive plain text. Transport-owned headers are regenerated with an explicit warning. Cookie objects, responses, timings, pages and extensions are disclosed as omitted.

Repeated headers, unsupported methods, missing captured nonempty bodies, multipart bodies, file parameters and encoded/binary body extensions reject the log instead of silently importing an altered request. No archive, file references, traffic or scripts are executed. Bulk Apply and request-only HAR export remain open, so IO-06 stays partial. Four tests bring the suite to 134: BOM/multiple entries/auth, exact URL query spelling, raw/ordered duplicate forms, unrepresentable/missing bodies and input/depth/count/version bounds. Existing secure Apply tests exercise the reused transaction. Installed-app selection/preview and external HAR producer interoperability remain manual acceptance items.

Primary format reference: the [historical HAR format draft](https://webperfwg.org/specs/HAR/Overview.html), checked 2026-10-24. It is an abandoned draft, not a current W3C standard.
