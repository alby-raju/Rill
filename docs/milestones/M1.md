# M1: Workspace, editing and recovery

Status: implementation delivered; acceptance remains partial until installed-app checks are recorded. No original implementation or assets were used. No external dependency was added.

## Implemented behavior

WORK-01–10: empty collection creation, rename/count-confirmed deletion; request duplication/move preserving all fields; drag and keyboard ordering within collections without deleting filtered siblings; persistent tabs with pin/reopen; separate drafts and explicit Save/Discard/Cancel; global request/collection/environment/session-history search; inherited environments; recursive variables; REST/JSON/Bearer/GraphQL POST templates. Parent cycles, missing parents and chains beyond 64 levels are rejected. Deleting a parent detaches its children and retains their local values. Disabled child values leave enabled parent values available.

EDIT-01–05: native text editing with JSON/XML/form/template colors, line numbers, find-next, wrap, shared code-font zoom and native undo; key and environment suggestions; automatic/side-by-side/stacked layout with native divider persistence; save/close/reopen and ordering menu shortcuts. JSON formatting changes whitespace outside strings only, preserving duplicate keys, escapes and number spellings. Highlighting is capped at 1 MiB; formatting input is capped at 8 MiB and output at 32 MiB. The automated large-editor fixture verifies formatting, not UI responsiveness.

Request edits stay in `EditorSessionState` rather than changing saved requests. Save commits drafts through the existing conflict-aware workspace actor. Closing a dirty tab or quitting requires a decision. Cancelling quit returns to the app directly. Structural workspace changes still autosave. Execution uses the visible draft; edits/navigation cancel active work and stale results remain guarded.

SAFE-01–03: draft checkpoints run every two seconds when changes are pending, separately in `editor-session.json`. Tabs, pinned state and up to 100 drafts survive restart; startup asks whether to recover unsaved drafts. Sidecar writes use bounded JSON, private atomic replacement, a cooperative lock and content-revision conflict checks. An invalid checkpoint is preserved and cannot be silently replaced. Forced termination can lose edits since the last successful checkpoint. Saved requests and draft recovery use separate Keychain services; credentials never appear in sidecar JSON.

Native `.rillbackup` files contain a versioned, checksummed JSON payload with a saved workspace and optional drafts. They omit auth credentials and response history. Ordinary headers, body text, URLs and environment values remain as entered, so the UI discloses that backups may contain sensitive data. This is a new Rill format, not a Relay ZIP importer. No archive entries are extracted: ZIPs, unknown versions, changed checksums, excessive sizes/depth and invalid references are rejected. The checksum detects accidental modification; it does not authenticate the file.

Restore validates before asking to replace the workspace, flushes existing structural changes, retains a new exclusive pre-restore backup and rejects overwriting an existing recovery copy or the active workspace. It checks the workspace revision again before committing, cancels active requests, replaces stale editors and reloads matching local Keychain entries. Failures after attempting restore pause writes and require reopening to establish the current disk state. Workspace, sidecar and Keychain remain separate stores; this is recoverable replacement, not a single atomic transaction across all three stores. Existing local keys are retained for rollback; exported backups cannot transfer those keys to another Mac.

Variable expansion supports nested references across URL, query, headers, body and auth, rejects missing/cyclic references, and bounds recursion (32), substitutions (10,000), individual variable output (1 MiB) and aggregate request expansion (32 MiB).

## Evidence and remaining checks

The full suite passes locally: 56 tests, including 19 new tests in `WorkspaceWorkflowTests` and `EditorRecoveryTests`. They cover saved/draft isolation, dirty-close decisions, tabs/pins, sidecar restart and conflicts, corrupt-file preservation, secret omission, tampered/unsupported backups, pre-restore retention/overwrite refusal, filtered-order preservation, full-field duplication, inheritance/import identity remapping, nested-variable cycles/budgets, fresh templates, global search and lossless JSON formatting. CI runs the same tests on the three macOS configurations described in M0.

Pending manual acceptance: drag/drop under filtering, keyboard and focus behavior, editor undo/completion/find and 100 KB typing responsiveness, divider restoration at different window sizes, search navigation, Save/Discard/Cancel/quit paths, forced termination recovery timing, actual Keychain denial, restore failure/reopen and two installed app instances. XML/form colors and accessibility need visual validation. All M1 rows remain partial until their relevant acceptance evidence is complete; test counts do not establish UI parity.
