# M6: GraphQL and live protocols

Status: implemented bounded native baseline; automated fixture evidence below. Installed-app, real-provider and accessibility acceptance remain open. No reference implementation, assets or tests were reused.

The GraphQL request tab edits a query, JSON-object variables and optional operation name alongside the existing endpoint/auth/header/TLS controls. Enabling it owns a POST JSON body and Content-Type; variables preserve exact JSON numbers and duplicate keys reject. Drafts may remain unfinished; sending validates them. HTTP status and GraphQL envelope/errors have separate checks. This is not a local GraphQL grammar/type validator. Native backups retain configuration; foreign collection exports explicitly refuse structured GraphQL rather than silently losing its body. Frozen client/HAR exports use the generated HTTP body.

Introspection is an explicit authenticated POST, or an opt-in debounced action when the endpoint changes while the editor is visible. Imports disable the opt-in. Failed/disabled introspection does not retry. Automatic introspection skips insecure TLS; manual connections require confirmation. Saved bounded introspection JSON reloads offline and supplies field/type/argument/input/enum name prefix completion through Ctrl+Space or Escape. The completion list is not a type-aware language server. Schemas and queries may contain sensitive information and are ordinary workspace metadata. Responses cap at 8 MiB, with 10,000 types and 20,000 completion names.

Request → WebSocket / SSE / Subscriptions opens an explicit live endpoint connection using the selected request's native auth, headers, variables and TLS profile. The transient timeline retains at most 1,000 records and 8 MiB; text previews cap at 64 KiB and binary previews at 8 KiB. Messages do not enter durable history or reports. Closing, changing mode/selection or disconnecting cancels owned work. No automatic reconnect or replay occurs.

WebSockets use URLSessionWebSocketTask with ws/wss, native trust/client identity handling, explicit text or base64-binary send and ping. Native framing handles fragmentation and control messages. Messages cap at 1 MiB, concurrent sends at 16/4 MiB, and sessions at five minutes. Connection/send/ping operations have deadlines; selected subprotocols must match. Redirects refuse. Incoming and outgoing records, generic errors and close events consume the shared timeline budget. Transport failures do not expose underlying credential-bearing NSError details.

GraphQL subscriptions implement graphql-transport-ws only: negotiated protocol, connection_init JSON, acknowledgement deadline, one operation ID, subscribe/next/error/complete, ping/pong and explicit completion/cancellation. The selected query and exact variables form the operation payload. Init JSON can use named-secret templates and its expanded payload is omitted from the timeline. Server payloads can themselves contain secrets. Legacy subscriptions-transport-ws is not implemented. No auto-resubscription or resume guarantee is claimed.

SSE uses native streaming HTTP with GET, requires status 200 and text/event-stream, refuses redirects, and bounds total bytes to 8 MiB/1,000 events. Incremental parsing handles UTF-8 replacement, leading BOM, CR/LF/CRLF, data line joins, event names, persistent/reset IDs, comments and bounded retry metadata. Lines cap at 64 KiB and events at 1 MiB. EOF does not dispatch an unfinished event. Retry is displayed metadata; it never silently starts another request. Stalled streams cancel through owned tasks and have a five-minute resource lifetime.

## Evidence

218 local tests pass, including eight independently authored live-protocol cases. A stdlib loopback fixture exercises actual GraphQL HTTP/introspection and server errors, exact variable numbers, offline schema reload, real SSE chunking/cancellation/MIME refusal, native WebSocket fragmented text/binary echo/ping/oversize refusal, and subscription negotiation/init/ack/ping/next/complete/timeout. Imported automatic introspection is disabled. Existing HTTP/TLS/upload/import/runner/contract tests remain green. Required CI also builds/packages the app on three macOS configurations and executes the 72 generated SDK requests. These checks do not substitute for installed-app or independent external-server acceptance.
