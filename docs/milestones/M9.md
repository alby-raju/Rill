# M9 — help, identity and release preparation

Rill now has an independently drawn app icon (reproducible Swift/AppKit source in scripts/make-icon.swift), searchable bundled offline help covering visible tools, privacy/limits/shortcuts and release boundaries, a native Help menu, explicit icon-button accessibility labels, and a DocC overview for the public RillCore module. Existing native appearance, editor zoom, focus and keyboard controls remain in place. VoiceOver reading order, focus restoration, contrast and reduced-motion behavior require installed-app human acceptance; no automated count substitutes for that review.

Version 0.2.0/build2 is synchronized across RillVersion, CLI help and app bundle. Packaging stages a clean app with icon, all SwiftPM resources, CLI at Contents/Helpers/rill, official protoc/includes, third-party notices and any required Swift compatibility runtime. Nested executables and app receive verified ad-hoc development signatures. release-artifacts.sh creates an architecture-specific compressed DMG, checksum and provenance (source revision, dirty flag, lockfile/notices hashes). sign-and-notarize.sh provides the separate Developer ID/hardened-runtime/notarytool/stapling/Gatekeeper path for app and DMG. No signing identity or notary credentials are committed; that distribution path must be exercised with actual credentials before publishing.

The CI matrix checks source on Intel and Apple Silicon, packages the app and runs native tests plus generated SDK programs. These are not fresh-machine installed-artifact results. docs/RELEASE.md records exact remaining gates and development release notes. No parity release, tag or notarization success is claimed. Each existing partial row retains its previous acceptance requirement; completion requires evidence or an explicitly owner-approved deviation. The register is an auditable inventory, not a percentage inferred from implemented menus.

Owner decision, 2026-10-25: paid Developer ID signing/notarization is deferred for now. Development builds and PR work continue; signing tooling is retained for a future release. The Intel cold-build CI budget is 45 minutes after a run passed release packaging but reached the previous 30-minute limit during debug test compilation; every existing required job/test remains enabled.
