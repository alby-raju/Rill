# M4: Workflows, execution and reports

Status: implementation in progress; manual installed-app acceptance remains pending. All code and fixtures are independently authored.

The Request Workflow tab persists optional declarative assertions, extraction rules and explicit native pre/post hooks. Legacy status/body checks still work. The shared workflow engine serves desktop Send, collection execution, matrix and load; command/client generation runs the same enabled pre-hook once before freezing. Native imports always disable hooks; foreign source remains a separate immutable disabled type. Saved requests, duplicate/move, backups and draft recovery retain source/flags; malformed unfinished source can be saved and fails before execution.

Assertions support status equality, header existence/contains, UTF-8 body contains and exact JSON equality through JSON Pointer or simple `$.field[0]` selectors. Wildcards, filters, malformed/missing values and duplicate JSON keys fail. JSON uses exact normalized decimal and literal decoded UTF-8 semantics. Extractions support headers and JSON values, reject duplicate target variables, and commit as one run-local update only after checks and the post-hook succeed. Object/array extractions serialize valid JSON; scalar strings are unquoted runtime values. Saved environments never change.

Request → Collection Runner / Matrix / Load uses saved snapshots with visible target selection. It supports saved order, 1–10,000 iterations/base steps/executions, 0–5 explicit retries, 0–60,000 ms request/retry pacing, stop/continue, per-attempt progress, cancellation, ID/unique-name branching and explicit stop. Retry attempts repeat hooks from the previous successful variable state. Invalid branches and failed hooks do not propagate updates. Repeated visits retain distinct outcomes; a later successful visit cannot erase an earlier failed visit. Empty, cancelled and exhausted runs cannot pass. An explicit successful hook stop may pass while skipped requests are marked not run. Without assertions, HTTP response receipt is successful regardless of status; configure status checks for API expectations.

Retained response bodies share 32 MiB per collection run; metadata/check outcomes and SHA-256 fingerprints remain after body retention is exhausted. A matrix divides this retention budget across 1–16 environments, concurrency 1–4, with isolated variables/hooks and stable result order. Comparisons use final observed status/checks/fingerprint per request and flag not-run requests. Fingerprint differences may reflect dynamic data; they are not proof of contract drift. Per-iteration matrix comparison is not yet exposed.

Load tests select one saved request/environment, 1–10,000 requests, concurrency 1–64 and ramp up to 60 seconds. Latency measures the complete shared workflow after ramp waiting, including hooks; samples retain status/state/latency only; no bodies or variables. In-flight body download budgets divide 32 MiB among concurrent workers (up to native per-request maximum), not a hard process/RSS sandbox. Success means execution and configured checks passed. Metrics use completed executions/elapsed monotonic time for throughput and nearest-rank min/p50/p95/p99/max; cancelled/not-run samples are excluded from percentiles. Load cancellation marks unstarted samples explicitly.

JSON, Markdown, JUnit XML and standard Allure `*-result.json` reports allowlist IDs, timings, status and generic checks/failures. They omit URLs, request/environment names, headers, bodies, fingerprints, variables and hook logs by default. JUnit keeps every retry attempt as a separate testcase, so a failed attempt remains a failure even when the overall run recovers. Empty runs emit explicit unsuccessful report entries; cancelled/remaining requests are skipped. Allure contains per-attempt status/stage/timestamps, without attachments/logs. Single-file exports are private/atomic; multi-file exports stage a private new directory before rename and never overwrite an existing report directory. Matrix export uses numbered environment files, not sensitive names. Load metrics export only bounded numeric samples.

## Native hook language

`json-operations-v1` is a finite JSON array, not JavaScript. Enable reviewed hooks explicitly. Sources and logs may contain secrets and stay local/plain text. Source is limited to 256 KiB, static/active operations to 1,024, conditional depth to 16, execution checks to 250 ms, run variables to 1,024/4 MiB, one expanded value/body to 1 MiB, request URL to 256 KiB, headers to 1,000/256 KiB, and logs to 32/16 KiB. Deadlines are checked between bounded operations; this is not an OS sandbox or a hard preemptive deadline inside Foundation calls. Loops/eval/unknown operations and JavaScript reject before execution. [Runtime decision](../decisions/hook-runtime.md).

Operations (every field is a string except conditional arrays):

| Operation | Fields | Behavior |
|---|---|---|
| `set`, `unset` | `name`, optional `value` | Runtime variable update/removal |
| `url`, `body` | `value` | Replace request URL or raw text body |
| `header` | `name`, `value` | Replace one header case-insensitively |
| `assert` | `value`, `equals` | Add exact string check |
| `extract` | `name`, `kind` (`json`/`header`), `selector` | Read response into variable; post-hook only |
| `sha256` | `name`, `value` | UTF-8 SHA-256 hex |
| `hmac` | `name`, `key`, `value` | UTF-8 HMAC-SHA256 hex |
| `time`, `uuid` | `name` | Unix milliseconds or UUID |
| `next` | `value` | Choose request ID or unique name; post-hook only |
| `stop` | none | Explicit collection stop; post-hook only |
| `log` | `value` | Bounded local log, excluded from reports |
| `if` | `value`, `equals`, `then`, optional `else` | Execute one finite operation array |

String fields resolve `{{variable}}` templates. Reserved context reads include `request.url`, `request.body`, `response.status`, lowercased `response.header.NAME`, `response.body` (1 MiB preview) and `response.bodyTruncated`. Reserved contexts cannot be assigned as variables. Hooks cannot directly read named Keychain/process secrets; signing values must be deliberately supplied as run-local values. Hook logs are bounded transient interpreter output, not displayed or exported by the runner yet. Post-hook request mutations do not persist to later requests; use variables for chaining.

Offline dynamic templates work anywhere native variables expand: `{{$uuid}}`, `{{$timestamp}}` (Unix seconds), `{{$email}}` (`example.test`) and `{{$randomInt -2 7}}` (inclusive validated bounds). Every occurrence generates independently, including inside nested variables. A hook can assign a generated value once to reuse it across request fields. Unknown generators fail; no external service is contacted.

## Evidence and remaining acceptance

Tests cover rules/exact JSON/missing selectors, transactional extraction/JSON serialization, deterministic SHA/HMAC vectors, conditional mutation, rejected loop/eval/host access/unknown fields/unreachable invalid branches, resource budgets, dynamic independence, retry/order/retention/report redaction, branch exhaustion/rollback, cancellation during pacing, percentile math, native hook import/persistence, real loopback extraction/post-hook rollback, matrix isolation and load, and shared pre-hook snippets. Concurrency-peak and in-flight/load cancellation checks also pass. Installed-app/export and independent Allure consumer acceptance remain to be completed before capability rows can become verified.

Headless APIs are shared and public; the dedicated CLI is M8. General-purpose JavaScript execution, direct Keychain hook access and per-iteration matrix diff are explicitly not claimed. The capability register remains partial rather than equating this implementation with full protocol or UI acceptance.

Primary references checked 2026-10-24: [RFC 6901 JSON Pointer](https://www.rfc-editor.org/rfc/rfc6901) and [Allure result-file documentation](https://allurereport.org/docs/how-it-works-test-result-file/). No external runtime or reference implementation was copied. Report generation caps 100,000 check entries before serialization and 32 MiB final output.
