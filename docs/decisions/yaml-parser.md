# Bounded YAML dependency decision

Reviewed 2026-10-24 for IO-05/09 and later specification import. Use exact Yams 6.2.2, the latest published release on review (2026-05-26), from [official upstream](https://github.com/jpsim/Yams/releases/tag/6.2.2). Its Swift 6 manifest builds Swift Yams plus bundled CYaml without other package dependencies; Rill remains macOS 14+, and the full Intel/Apple Silicon/Xcode matrix must pass before merge. No Relay code/runtime is used. Pin the resolved revision in Package.resolved.

Yams and bundled libyaml carry MIT notices. THIRD_PARTY_NOTICES.txt includes their notices and is copied into the app bundle before signing. No external parser installation or runtime download is needed. Official notices: [Yams](https://github.com/jpsim/Yams/blob/6.2.2/LICENSE), [libyaml](https://github.com/yaml/libyaml/blob/master/License).

The public upstream Yams and libyaml security-advisory endpoints returned no published advisories on review. The bundled C snapshot is pinned by Yams revision `a27b21e0c81c5bf42049b897a62aaf387e80f279`; no separate current-libyaml version claim is made. This is not a claim of absence of vulnerabilities; review the bundled C parser as well when upgrading. We do not accept arbitrary YAML constructors or include/file/network directives. A libyaml event preflight rejects aliases/anchors, custom tags, multiple documents, depth over 64, more than 100,000 events and scalar values over 1 MiB, with an 8 MiB input cap, before constructing a Swift tree. Only JSON-compatible values are accepted. A custom JSON-like scalar resolver keeps unquoted yes/off/date strings as strings, avoiding YAML 1.1 boolean/timestamp surprises. Duplicate mapping keys fail. Detailed upstream parse errors are replaced with content-free errors because they can embed source text. Parsing is off the UI executor and cancellation is checked between events.

The preflight imports CYaml, the bundled module in the pinned package product's build closure; this is a deliberate dependency on that module layout. An upgrade must prove that API/build compatibility and rerun malicious depth/alias/tag/duplicate/multi-document fixtures, round trips and packaging/notices verification. Do not silently remove limits to accommodate a library change. Removal requires replacing the bounded YAML adapter while preserving these tests; formats using it otherwise fail explicitly. Keep YAML subset limitations visible in the import preview/docs. This is a bounded parser integration, not an OS process sandbox or a hard wall-clock guarantee for C parsing of a bounded token.
