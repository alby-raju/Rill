# Generated client SDK validation (2026-10-24)

The app gains independently authored text templates, not runtime SDK dependencies. Generated programs are never executed by Rill. Test-only isolated environments compile/run synthetic programs against loopback; do not pass personal workspaces or credentials to this harness.

Targets: Python requests (Apache-2.0) and HTTPX (BSD-3-Clause), Node built-in fetch and axios (MIT), Java 21 HttpClient (JDK), Java OkHttp JVM (Apache-2.0), Go net/http (BSD-3-Clause), Rust reqwest (MIT/Apache-2.0) with base64 (MIT/Apache-2.0), and .NET HttpClient (MIT runtime). Install tools/SDKs only in disposable test environments or CI. None is copied into the macOS app; there are no new app notices or CPU-dependent native app libraries. Swift 6 templates work on both supported architectures.

Pinned validation versions start with requests 2.34.2, HTTPX 0.28.1, axios 1.20.0, OkHttp JVM 5.3.2, reqwest 0.13.5 and base64 0.22.1. Current official API documentation was reviewed on the date above. These libraries have active upstream documentation; this is not a comprehensive security audit. Inspect package advisories on upgrades; CI test installation can fail closed if an exact version becomes unavailable. SDK tests may download transitive libraries; app builds retain only existing pinned Swift packages.

Sources: [requests](https://requests.readthedocs.io/en/latest/api/), [HTTPX](https://www.python-httpx.org/api/), [Node](https://nodejs.org/api/globals.html#fetch), [axios](https://axios-http.com/docs/req_config), [Java](https://docs.oracle.com/en/java/javase/21/docs/api/java.net.http/java/net/http/HttpClient.html), [OkHttp](https://square.github.io/okhttp/), [Go](https://pkg.go.dev/net/http), [reqwest](https://docs.rs/reqwest/latest/reqwest/blocking/struct.ClientBuilder.html), [.NET](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.httpclient.sendasync).

All generators share a bounded frozen request, retain exact body bytes/boundary, cap source output, mask known/custom auth headers, reject unsupported transport/header settings and emit response caps. SDKs can normalize URLs, supply default headers, and implement different timeout semantics. Clients disable redirects; this conservatively differs from native same-origin redirects. Java streaming has a separate body-read deadline. Dependency comments are hints, not an installed SDK or browser compatibility claim. Credentials are embedded only on explicit opt-in; URL/body/uncommon headers remain user-review material. Removing a target requires only its template and validation configuration; no workspace migration is needed.
