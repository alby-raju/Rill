# Bounded ZIP dependency decision

Reviewed 2026-10-24 for IO-07/09. Pin [ZIPFoundation 0.9.20](https://github.com/weichsel/ZIPFoundation/releases/tag/0.9.20), latest published release on review (2025-09-24). Upstream is not archived and was pushed 2026-09-12. It is Swift-native and uses Apple's Compression framework on macOS, with a Swift 5.9 manifest compatible with Rill's Swift 6/macOS 14 floor. Full Intel/Apple Silicon/Xcode CI and packaging must pass before merge. The upstream manifest emits a harmless watchOS deployment deprecation warning under Xcode 26; Rill targets macOS 14 and does not modify that upstream manifest. No Relay implementation/dependency is reused.

MIT notices are appended to THIRD_PARTY_NOTICES.txt. SwiftPM's generated resource bundle contains the dependency privacy manifest and is copied into app Resources before signing. The pinned package has no runtime resource reads needed for extraction; reevaluate Bundle.module lookup/packaging if an upgrade adds any. No external unzip executable or runtime download is needed. [Official license](https://github.com/weichsel/ZIPFoundation/blob/0.9.20/LICENSE), [package manifest](https://github.com/weichsel/ZIPFoundation/blob/0.9.20/Package%40swift-5.9.swift).

The public upstream security-advisory endpoint returned no published advisories on review; this does not prove absence of vulnerabilities. Independently validate ZIP metadata before opening the archive: one disk, ordinary ZIP (no ZIP64/encryption/SFX), stored/deflate methods, consistent directory/local headers and descriptors, UTF-8 safe paths, no symlink/special files, no overlapping ranges or normalized path collisions. Limits: 32 MiB compressed and expanded total, 4 MiB per file, 4,096 entries, 16 path components and 1,024 path bytes. Reject nested archives. No archive is extracted to disk. Folder ingestion reads only `.bru` and `bruno.json`, skips `.git`/`node_modules`, and never opens upload or `.env` contents. It refuses a selected root symlink, canonicalizes macOS ancestor aliases with realpath, then uses descriptor-relative openat/O_NOFOLLOW for every imported path component. Each regular file is size-bounded and checked for changes during its read. Stream decompression in 64 KiB chunks with independent actual byte limits, cancellation, size and CRC verification.

Upgrades must retain malicious metadata/path/symlink/bomb/CRC/cancellation tests and recheck privacy resources, supported CPU/toolchain builds, notices and public advisories. Do not relax limits to accommodate a library change. Removing the package requires replacing only the bounded archive adapter while preserving those gates; unsupported archive representations otherwise fail explicitly. This is a bounded in-process parser, not an OS sandbox or a hard C-decompression wall-clock guarantee. Metadata layout follows [PKWARE APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT).
