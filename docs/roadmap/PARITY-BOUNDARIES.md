# Parity boundaries and audit findings

Reference: supplied Relay 1.0.0 archive, audited 2026-10-24. These are reference claims and limits, not verified properties of Rill or independent certification of Relay. Evidence keys resolve through [reference-inventory.json](reference-inventory.json).

## What was checked

Product README, user guide, roadmap, modern workflow guide, UI system, release notes, validation claims, transport notes, packaging/release instructions and Kafka packaging notes were read. Maintained production and test file entry points were inventoried; CLI command dispatch/help, body/auth/response-format choices, templates, advanced tool navigation, public API signatures and named test scenarios were inspected to find omissions from headline documentation.

This is a requirements audit, not a line-by-line behavioral review of every method. The manifest maps all scoped files to capability owners, including module/build helpers. Hashes make the exact baseline identifiable without placing the old source in the public repository. The archive's claim of 107 passing tests is not reproduced here and is not Rill evidence.

The inventory intentionally excludes generated Javadoc (a duplicate view of declarations), bundled third-party legal documents, IDE metadata and macOS metadata. Rill still needs new third-party notices for its own selected dependencies; exclusion here is not permission to omit licenses from distribution.

## Reference limits to carry into acceptance work

| Area | Reference baseline or boundary | Rill decision needed |
| --- | --- | --- |
| HTTP | Baseline download budget 16 MiB; accepted override range described as 1 KiB–256 MiB. Preview/history baseline 512 KiB. | Independently enforce download and preview/retention bounds, expose truncation, and record any new limits. Current Rill only has the 16 MiB download cap and session history cap. |
| Runs | Maximum 10000 executions and 32 MiB shared retained response bodies; checks/extraction use accepted full response even after retention budget is exhausted. | Preserve bounded execution and distinguish unavailable retained body from failed checks. |
| Cancellation | Reference runner cancels between steps/retries/pacing; in-flight HTTP obeys timeout. | Retain Rill's in-flight cancellation and extend it to all transports; record this improvement rather than inheriting a weaker behavior. |
| Recovery | Two-second draft checkpoints; possible loss since last successful checkpoint. Restore retains previous workspace and exits desktop to avoid stale overwrite. Backups include credentials. | Keep transactional recovery and explicit loss window; choose a safer explicit backup secret policy instead of copying secret-inclusive defaults unnoticed. |
| Scripting | Reference has opt-in hooks; disposable worker with 128 MiB heap, 8-second deadline, 200000 statements, 65536-character scripts and 1 MiB I/O. Host/file/network/environment/process/native/thread access is denied. It does not claim an OS sandbox. | Choose native isolation/resources independently, prove denied access and cancellation, document any differing limits. No Java worker/SDK source reuse. |
| Hook order | Pre-hook before substitution; post-hook after extraction; retries repeat hooks. Failed steps do not propagate post-response values. Branching is same-collection and stops on assertion failure when configured. | Freeze and test these semantics; clarify exact signing text and runtime variable lifetime. |
| Dynamic values | UUID, seconds timestamp, synthetic email, inclusive random integer; each occurrence independent. Nested variable/secret references also exist. | Keep generated values offline; store run-local value when consistency across fields is needed. |
| OpenAPI/schema | Swagger 2 and OpenAPI 3.x JSON/YAML; local references. Supported schema keywords are enumerated in SPEC-05. External refs are not fetched; unsupported rules must be reported. | Publish supported versions/keywords explicitly; never advertise full standards conformance from this baseline. |
| Contract tests | One linked positive test per operation, documented success status when available; users must fill examples, path values and credentials. | Negative/boundary case generation is beyond baseline and should be scoped separately. |
| GraphQL | Prefix completion from introspection, not a language server. Servers may refuse introspection. Subscription protocol is graphql-transport-ws; legacy subscriptions-transport-ws absent. | Make auto-introspection visible/opt-in and preserve explicit unsupported cases. |
| gRPC | Proto/descriptor and reflection v1/v1alpha; well-known types; imports beneath selected proto directory. Four call modes. Standard trust; custom HTTP TLS profiles/additional include roots not exposed. CLI sends one message then finishes input. | Native default with no grpcurl dependency. Additional proto roots/custom trust or optional grpcurl adapter are separate decisions, not implied parity. |
| Events | Baseline payload cap 1 MiB, bounded timeline/inflight work. CloudEvents structured JSON 1.0 with parsed data and transport metadata where supported. | Apply limits to all entry points, including malformed and fragmented packets. |
| Kafka | SASL/PLAIN baseline; verified default trust; consume latest without committing offsets; publish waits for acknowledgement. No admin/schema-registry/arbitrary-property editor promise. | Validate maintained native client and compression/runtime packaging; do not reuse Kafka JAR bundle. |
| AMQP | Existing queue, default exchange publishing and receive acknowledgement; no topology creation; verified TLS/hostname behavior. | Do not promise arbitrary exchange routing or topology management unless implemented and added to register. |
| Converters | Postman v2.1, Insomnia v4 JSON/v5 YAML, HAR, Bruno file/folder/ZIP; basic/bearer/common HTTP fields. Not all declarative tests, inheritance, OAuth, plugins, encrypted secrets or captured history transfer. | Explicit per-format support table, preview warnings and no destructive lossy exports. HTTPie Desktop import is a separate capability from HTTPie CLI parsing. |
| File interchange | Import baseline 32 MiB and 4 MiB per ZIP entry; paths validated. File bodies remain references, not attached files. Bruno export excludes file/form bodies; HAR uses explicit auth headers and request-only placeholder responses. | Test expanded-size/entry-count/depth and symlink traversal too; list intentional improvements and changed limits. |
| Foreign scripts | No foreign SDK translation; some formats retain source disabled, others warn that migration is required. | Imported scripts never become runnable automatically; retention is not compatibility. |
| Snippets | cURL, HTTPie, requests/httpx, fetch/axios, Java HttpClient/OkHttp, Go, Rust and C#. Repeated headers require cURL; other targets reject. Multipart bytes/base64 embedding capped at 1 MiB; cURL retains file references. Some clients reject GET/HEAD bodies. | Per-target representability tests; mask credential headers by default but warn that URLs/bodies/file paths may still contain secrets. |
| Reports | JSON/Markdown/JUnit and Allure omit secret-bearing URLs, bodies, runtime values and sensitive failure details. Empty/cancelled runs cannot pass. Allure results need an external viewer. | Test using seeded secrets; distinguish generating result files from packaging a dashboard. |
| Scanner | Passive HSTS/CSP/sniffing/CORS; opt-in GET/HEAD one-parameter quote/reflection probes; sequential rate sample max ten. Findings are indicators, not complete DAST or proof of no rate limiting. | Test request budgets and explicit target consent; no automatic active scan on Send. |
| Matrix/performance | Matrix 1–16 environments, concurrency 1–4, isolated state, status/check/body fingerprints. Dynamic content can differ; unrun steps are explicit. Load tool supports ramp-up and reports throughput and latency percentiles. | Do not label nondeterministic body differences as regressions without context. |
| Named secret providers | Native secrets plus read-only normalized process-environment lookup are separate from saved environment variables. | Add a Rill-specific prefix and explicit provider precedence for headless/CI use; never persist fallback values. |
| Sharing/plugins | Explicit token-protected read-only share; history/credential profiles excluded. Local plugins and service registration exist; reference plugins are Java-specific. | New native contract and trust model; sanitized sharing must not copy runtime secrets or execute plugins implicitly. |
| macOS release | Reference includes app/DMG, optional signing/notary/stapling, per-CPU packaging and bundled compiler/runtime. Target-Mac and real broker/TLS checks remain caveats. | Match user outcomes with Swift tools; Java/jlink/Maven compatibility is not a Rill product requirement. Test installed signed app, CLI and Keychain on claimed targets. |

## Conflicts and compatibility decisions to settle

1. **MQTT documentation disagrees.** The modern workflow guide describes Paho-supported WebSocket schemes; the dedicated transport guide and module notes say Vert.x replaced Paho, describe verified TLS, bounded binary bridging and no automatic reconnect/redirect. Use the dedicated transport guide plus MQTT test scenarios as the functional requirements and revalidate independently. Neither Java dependency is a required Swift implementation choice.
2. **gRPC default versus compatibility adapter.** Native transport is the documented default; a legacy external adapter remains in the reference core. Cover the default completely. Keep optional adapter compatibility as an explicit GRPC-05 decision, rather than accidentally depending on grpcurl.
3. **Rill layout differs intentionally.** Reference UI prefers a large side-by-side response; current Rill is stacked. Preserve a readable adaptive composition/inspection experience and add wide-layout choice. Do not copy Carbon colors, pixel values, icons, custom JavaFX file dialogs or branding; native sheets/pickers remain valid new design choices.
4. **Safety can improve without losing workflow breadth.** Existing Rill cancels in-flight HTTP and excludes auth credentials from native exports. Do not regress those improvements to match weaker defaults. Add explicit policy for secret-bearing bodies/headers/history/backups/share/snippets; Keychain storage alone does not solve all redaction.
5. **Claims are narrower than names.** A feature named Contracts, Scanner, Plugins or GraphQL does not imply complete schema conformance, full DAST, arbitrary Java plugin compatibility or language-server intelligence. Keep supported subsets visible in UI, docs and acceptance fixtures.
6. **Platform/runtime mechanics are not portable capabilities.** Frozen original JUnit files, Java module metadata, JDK fallbacks, JavaFX typography and old scripts/assets are reference implementation details. New regression scenarios, native packaging and new branding replace them without code reuse.
7. **Parity is not a maintenance guarantee.** Before selecting any Swift dependency or adopting a new protocol/spec version, check its current official support, security and licensing information. Record the decision separately; old version numbers in the archive are not approved dependencies.

A capability owner must resolve a conflict before marking the affected row verified. Record owner-approved omissions/replacements as deviations with linked decisions; do not remove inconvenient rows.
